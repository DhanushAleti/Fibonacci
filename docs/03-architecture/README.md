# 03 · Architecture

**Status:** Draft
**Last Updated:** 2026-08-02

## Purpose

Document the system architecture of Project PHI: components, data flow, integration points, and technical decisions at a system level.

## Scope

Covers high-level and mid-level architecture. Component-specific implementation detail lives in 07-backend / 08-frontend; formal decision records live in 18-decisions.

## What Belongs Here

- System diagrams
- Component and integration maps
- Technology stack overview
- Non-functional requirements (scalability, reliability, etc.)

## Naming Convention

Use kebab-case markdown files, e.g. `system-overview.md`, `data-flow.md`.

## Example Files

- `system-overview.md`
- `tech-stack.md`
- `data-flow.md`

## Best Practices

- Keep diagrams close to the docs that describe them
- Update architecture docs whenever a structural change ships
- Reference ADRs (18-decisions) rather than re-explaining rationale here
