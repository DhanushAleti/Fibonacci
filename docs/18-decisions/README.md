# 18 · Decisions

**Status:** Draft
**Last Updated:** 2026-08-02

## Purpose

Maintain Architecture Decision Records (ADRs) capturing significant technical and product decisions and their rationale.

## Scope

Covers point-in-time decisions with context, options considered, and outcome. Does not cover general architecture description, which lives in 03-architecture.

## What Belongs Here

- ADRs
- Decision context, alternatives considered, and consequences

## Naming Convention

Use a numbered prefix plus kebab-case, e.g. `0001-use-postgresql.md`.

## Example Files

- `0001-use-postgresql.md`
- `0002-adopt-fastapi.md`

## Best Practices

- Use the ADR_TEMPLATE.md in 15-templates for every new decision
- Never delete or rewrite a past ADR; supersede it with a new one instead
- Number ADRs sequentially and never reuse a number
