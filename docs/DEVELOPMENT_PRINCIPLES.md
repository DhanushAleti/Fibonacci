# PHI Development Principles

## 1. Source of Truth
Important product and technical decisions should be represented in version-controlled documentation.

## 2. Incremental Implementation
PHI should be developed in small, testable phases rather than attempting the entire system at once.

## 3. Evidence First
Automated processes should rely on verified source data instead of assumptions.

## 4. Explicit Unknowns
Missing or unverified information should remain explicitly unknown until reliable data is available.

## 5. Test Before Expansion
New backend capabilities should be validated before becoming dependencies for later phases.

## 6. Traceability
Changes should remain understandable through documentation, commits, and tests.
