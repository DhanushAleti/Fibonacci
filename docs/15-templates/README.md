# 15 · Templates

**Status:** Draft
**Last Updated:** 2026-08-02

## Purpose

Provide reusable document templates for consistent documentation across Project PHI.

## Scope

Covers blank/starter templates only. Filled-in documents belong in their respective numbered sections, not here.

## What Belongs Here

- PRD, feature, API, research, bug, test plan, ADR, meeting, model card, and release templates

## Naming Convention

Use SCREAMING_SNAKE_CASE with a `_TEMPLATE` suffix, e.g. `PRD_TEMPLATE.md`.

## Example Files

- `PRD_TEMPLATE.md`
- `ADR_TEMPLATE.md`
- `BUG_TEMPLATE.md`

## Best Practices

- Keep templates generic and reusable across teams/agents
- Update all filled-in docs when a template's structure changes, or explicitly version templates
- Do not fill in real content directly inside a template file
