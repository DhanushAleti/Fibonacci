# 16 · Workflows

**Status:** Draft
**Last Updated:** 2026-08-02

## Purpose

Document standard operating workflows and processes used to build and ship Project PHI.

## Scope

Covers repeatable, step-by-step processes. Does not cover one-off decisions, which live in 18-decisions.

## What Belongs Here

- Feature, bug, research, model training, deployment, release, and code review workflows

## Naming Convention

Use SCREAMING_SNAKE_CASE with a `_WORKFLOW` suffix, e.g. `FEATURE_WORKFLOW.md`.

## Example Files

- `FEATURE_WORKFLOW.md`
- `BUG_WORKFLOW.md`
- `RELEASE_WORKFLOW.md`

## Best Practices

- Keep workflows actionable and step-based, not descriptive prose
- Update a workflow doc as soon as the real process changes
- Reference relevant templates from 15-templates within each workflow
